## **概念 → 为什么重要 → 最小示例 → 动手试试 → 要点**

**概念**：任务就像工厂里的工人，每个都有特定的工作要做。RTOS 就像一个聪明的管理者，确保每个工人获得足够的时间和资源来按时完成工作。

**为什么重要**：如果没有恰当的任务管理，你的嵌入式系统就像没有管理者的工厂——工人们互相碰撞，资源被浪费，截止时间被错过。良好的任务管理确保一切顺畅、可预测地运行。

**最小示例**：一个包含三个任务的简单系统：一个每 100ms 闪烁一次 LED，另一个每 500ms 读取一次传感器，第三个每 1000ms 发送一次数据。每个任务独立运行，但系统协调所有任务。

**动手试试**：从单个任务开始，然后添加更多任务并观察 RTOS 如何管理它们。改变优先级并观察它如何影响执行顺序。

**要点**：任务管理关乎设计能够有效协作的独立工人，由 RTOS 处理复杂的协调，让你专注于每个任务应该做什么。

## 📋 **速查表：关键要点**

### **任务基础**
- **独立执行(Independent Execution)**：每个任务拥有自己的上下文独立运行
- **并发操作(Concurrent Operation)**：多个任务可以同时就绪
- **调度执行(Scheduled Execution)**：RTOS 调度器确定哪个任务何时运行
- **资源共享(Resource Sharing)**：任务可以共享系统资源并通信
- **基于优先级(Priority-Based)**：高优先级任务可以中断低优先级任务

### **任务状态**
- **已创建(Created)**：任务存在但尚未被调度
- **就绪(Ready)**：任务已准备好运行，等待 CPU 时间
- **运行(Running)**：任务当前正在 CPU 上执行
- **阻塞(Blocked)**：任务在等待某物（延时、数据、资源）
- **已删除(Deleted)**：任务已从系统中移除

### **任务设计原则**
- **单一职责(Single Responsibility)**：每个任务应有一个清晰的工作
- **合适的粒度(Appropriate Granularity)**：既不太大也不太小
- **独立操作(Independent Operation)**：任务应能独立运行
- **清晰通信(Clear Communication)**：任务之间有明确界定的接口
- **资源效率(Resource Efficiency)**：合适的栈大小和内存使用

### **优先级指南**
- **高优先级 (4-5)**：紧急功能、安全关键操作
- **中优先级 (2-3)**：正常系统操作、数据处理
- **低优先级 (1)**：后台任务、状态更新、清理
- **优先级继承(Priority Inheritance)**：任务可以继承其所访问资源的优先级
- **优先级反转(Priority Inversion)**：低优先级任务可以阻塞高优先级任务

## 🧠 **核心概念**

### **什么是任务？**

任务是一个独立的工作单元，与其他任务并发运行。把它看作一个可以与其他程序同时运行的独立程序。

```
┌─────────────────────────────────────────────────────────────┐
│                    What is a Task?                         │
├─────────────────────────────────────────────────────────────┤
│                                                           │
│  Traditional Program:                                      │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  main() {                                          │   │
│  │    while(1) {                                      │   │
│  │      blink_led();                                  │   │
│  │      read_sensor();                                │   │
│  │      send_data();                                  │   │
│  │      delay(100);                                   │   │
│  │    }                                               │   │
│  │  }                                                 │   │
│  └─────────────────────────────────────────────────────┘   │
│  ❌ Everything runs in sequence                          │
│  ❌ Can't prioritize different operations               │
│  ❌ Hard to make operations independent                 │
│                                                           │
│  RTOS with Tasks:                                        │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐        │
│  │ Task 1:     │  │ Task 2:     │  │ Task 3:     │        │
│  │ Blink LED   │  │ Read Sensor │  │ Send Data   │        │
│  │ Every 100ms │  │ Every 500ms │  │ Every 1000ms│        │
│  └─────────────┘  └─────────────┘  └─────────────┘        │
│  ✅ Each task runs independently                          │
│  ✅ Different priorities possible                         │
│  ✅ Easy to add/remove/modify tasks                     │
└─────────────────────────────────────────────────────────────┘
```

### **为什么使用任务而不是一个大循环？**

**单循环问题：**
```
┌─────────────────────────────────────────────────────────────┐
│                    Single Loop Problems                    │
├─────────────────────────────────────────────────────────────┤
│                                                           │
│  while(1) {                                               │
│    // What if sensor reading takes too long?             │
│    sensor_value = read_sensor();                          │
│                                                           │
│    // LED blinking gets delayed!                          │
│    blink_led();                                           │
│                                                           │
│    // What if data sending fails?                        │
│    send_data();                                           │
│                                                           │
│    // Everything waits for everything else                │
│    delay(100);                                            │
│  }                                                        │
│                                                           │
│  ❌ One slow operation delays everything                  │
│  ❌ Can't prioritize critical operations                  │
│  ❌ Hard to handle failures gracefully                    │
│  ❌ Timing becomes unpredictable                          │
└─────────────────────────────────────────────────────────────┘
```

**基于任务的好处：**
```
┌─────────────────────────────────────────────────────────────┐
│                    Task-Based Benefits                     │
├─────────────────────────────────────────────────────────────┤
│                                                           │
│  Task 1 (High Priority):                                  │
│  while(1) {                                               │
│    blink_led();                                           │
│    vTaskDelay(100);                                       │
│  }                                                        │
│                                                           │
│  Task 2 (Medium Priority):                                │
│  while(1) {                                               │
│    sensor_value = read_sensor();                          │
│    vTaskDelay(500);                                       │
│  }                                                        │
│                                                           │
│  Task 3 (Low Priority):                                   │
│  while(1) {                                               │
│    send_data();                                           │
│    vTaskDelay(1000);                                      │
│  }                                                        │
│                                                           │
│  ✅ Each task runs at its own pace                        │
│  ✅ Critical operations (LED) aren't delayed              │
│  ✅ Failures in one task don't affect others              │
│  ✅ Timing is predictable and reliable                    │
└─────────────────────────────────────────────────────────────┘
```

## 🔄 **任务生命周期**

### **任务状态**

任务在其生命周期中会经历不同的状态：

```
┌─────────────────────────────────────────────────────────────┐
│                    Task State Machine                      │
├─────────────────────────────────────────────────────────────┤
│                                                           │
│  ┌─────────┐    ┌─────────┐    ┌─────────┐                │
│  │ Created │───▶│  Ready  │───▶│ Running │                │
│  └─────────┘    └─────────┘    └────┬────┘                │
│                                      │                     │
│                                      ▼                     │
│  ┌─────────┐    ┌─────────┐    ┌─────────┐                │
│  │Deleted  │◄───│ Blocked │◄───│         │                │
│  └─────────┘    └─────────┘    └─────────┘                │
│                                                           │
│  State Transitions:                                        │
│  • Created → Ready: Task is ready to run                  │
│  • Ready → Running: Scheduler selects this task           │
│  • Running → Ready: Task yields or is preempted           │
│  • Running → Blocked: Task waits for something            │
│  • Blocked → Ready: What task was waiting for happens     │
│  • Any → Deleted: Task is removed from system             │
└─────────────────────────────────────────────────────────────┘
```

### **每个状态会发生什么？**

**已创建**：任务存在但尚未被调度
**就绪**：任务已准备好运行，等待 CPU 时间
**运行**：任务当前正在 CPU 上执行
**阻塞**：任务在等待某物（延时、数据、资源）
**已删除**：任务已被移除，不会再运行

## 🎨 **任务设计原则**

### **单一职责原则**

每个任务应有一个清晰的工作：

```
┌─────────────────────────────────────────────────────────────┐
│                    Good vs Bad Task Design                 │
├─────────────────────────────────────────────────────────────┤
│                                                           │
│  ❌ Bad: One task does everything                         │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ void vDoEverythingTask(void *pvParameters) {       │   │
│  │   while(1) {                                        │   │
│  │     // Too many responsibilities!                    │   │
│  │     read_sensors();                                  │   │
│  │     process_data();                                  │   │
│  │     control_motors();                                │   │
│  │     update_display();                                │   │
│  │     send_telemetry();                                │   │
│  │     vTaskDelay(100);                                 │   │
│  │   }                                                  │   │
│  │ }                                                    │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                           │
│  ✅ Good: Each task has one job                          │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐        │
│  │ Sensor Task │  │ Control     │  │ Display     │        │
│  │ Read data   │  │ Task        │  │ Task        │        │
│  │ every 100ms │  │ Process &   │  │ Update UI   │        │
│  └─────────────┘  │ control     │  │ every 50ms  │        │
│                   │ every 50ms  │  └─────────────┘        │
│                   └─────────────┘                         │
│                                                           │
│  Benefits of good design:                                 │
│  • Easier to understand and debug                         │
│  • Can optimize each task independently                    │
│  • Easier to test individual components                   │
│  • More flexible and maintainable                         │
└─────────────────────────────────────────────────────────────┘
```

### **任务粒度**

任务既不应太大也不应太小：

**太大（粗粒度）：**
- 难以理解和调试
- 难以优化
- 响应性差
- 难以测试

**太小（细粒度）：**
- 过多上下文切换
- 内存开销
- 复杂协调
- 难以管理

**刚好合适：**
- 清晰、专注的职责
- 合适的执行频率
- 可管理的复杂度
- 良好的可测试性

## 🎯 **优先级管理**

### **为什么优先级重要**

当多个任务就绪时，优先级决定哪个任务运行：

```
┌─────────────────────────────────────────────────────────────┐
│                    Priority System                         │
├─────────────────────────────────────────────────────────────┤
│                                                           │
│  Priority 5: Emergency Stop (highest)                    │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ ██████████████████████████████████████████████████ │   │
│  │ Emergency stop - must run immediately!              │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                           │
│  Priority 4: Safety Monitoring                           │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ ██████████████████████████████████████████████████ │   │
│  │ Safety checks - critical for system safety          │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                           │
│  Priority 3: Control Loop                                 │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ ██████████████████████████████████████████████████ │   │
│  │ Main control - keeps system running                 │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                           │
│  Priority 2: Data Logging                                 │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ ██████████████████████████████████████████████████ │   │
│  │ Logging - important but not critical                │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                           │
│  Priority 1: Status Updates (lowest)                     │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ ██████████████████████████████████████████████████ │   │
│  │ Status - nice to have but not essential            │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                           │
│  ⚠️  Higher priority tasks can interrupt lower ones!      │
└─────────────────────────────────────────────────────────────┘
```

### **优先级分配指南**

**高优先级 (4-5)：**
- 紧急功能
- 安全关键操作
- 实时控制循环
- 中断处理程序

**中优先级 (2-3)：**
- 正常系统操作
- 数据处理
- 通信任务
- 常规监控

**低优先级 (1)：**
- 后台任务
- 状态更新
- 非关键日志记录
- 清理操作

## 💾 **资源管理**

### **栈管理**

每个任务需要自己的栈空间：

```
┌─────────────────────────────────────────────────────────────┐
│                    Task Stack Allocation                    │
├─────────────────────────────────────────────────────────────┤
│                                                           │
│  ┌─────────────────────────────────────────────────────┐   │
│  │                System Memory                        │   │
│  ├─────────────────────────────────────────────────────┤   │
│  │  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐ │   │
│  │  │ Task 1      │  │ Task 2      │  │ Task 3      │ │   │
│  │  │ Stack       │  │ Stack       │  │ Stack       │ │   │
│  │  │ 1KB         │  │ 2KB         │  │ 512B        │ │   │
│  │  └─────────────┘  └─────────────┘  └─────────────┘ │   │
│  ├─────────────────────────────────────────────────────┤   │
│  │                Heap (shared)                        │   │
│  ├─────────────────────────────────────────────────────┤   │
│  │                Global Variables                      │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                           │
│  Stack Size Considerations:                               │
│  • Too small: Stack overflow crashes                     │
│  • Too large: Wastes memory                              │
│  • Monitor actual usage with stack checking              │
│  • Consider function call depth and local variables      │
└─────────────────────────────────────────────────────────────┘
```

### **内存分配策略**

**静态分配：**
- 在编译时分配所有内存
- 内存使用可预测
- 无运行时分配失败
- 灵活性较低

**动态分配：**
- 根据需要分配内存
- 更灵活
- 有分配失败的风险
- 内存碎片化

## 🧪 **引导实验**

### **实验 1：单任务系统**
**目标**：理解基本的任务创建和执行。

**设置**：创建一个执行简单操作的单一任务。

**步骤**：
1. 创建一个闪烁 LED 的任务函数
2. 用合适的栈大小和优先级配置任务
3. 启动调度器并观察任务运行
4. 修改任务时序并观察变化

**预期结果**：理解基本任务创建以及任务如何独立运行。

### **实验 2：多任务协调**
**目标**：学习多个任务如何协同工作。

**设置**：创建两个需要协调工作的任务。

**步骤**：
1. 创建生成数据的生产者任务
2. 创建处理数据的消费者任务
3. 使用队列在任务之间传递数据
4. 观察任务如何在不干扰彼此的情况下协调

**预期结果**：理解任务通信和协调。

### **实验 3：优先级管理**
**目标**：学习优先级如何影响任务执行。

**设置**：创建多个具有不同优先级的任务。

**步骤**：
1. 创建具有不同优先级的任务
2. 让高优先级任务频繁运行
3. 让低优先级任务做繁重工作
4. 观察优先级如何影响执行顺序

**预期结果**：理解基于优先级的调度及其影响。
