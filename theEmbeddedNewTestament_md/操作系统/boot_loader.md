## 引导加载程序(boot loader)如何工作
### BIOS 为我们做了什么
BIOS 是 PC 的 ROM 中的固件。当 PC 上电时，BIOS 是第一个运行的程序。所有其他程序必须先被加载到 RAM 中。BIOS 包含以下部分:

  * POST(开机自检 Power On Self Test)。统计主内存千字节数的运行计数器是 POST 中最可见的部分。
  * 设置菜单(Setup Menu)，让你设置一些参数并调整实时时钟。大多数现代 BIOS 版本让你设置启动顺序，即 BIOS 检查启动的设备。这些可以是 A(第一个软盘)、C(第一个硬盘)、CD-ROM 以及可能其他磁盘。列表中的第一个设备会首先被尝试。较旧的 BIOS 只有一种启动顺序: A、C。所以 BIOS 会首先尝试从 A 启动，如果驱动器中没有软盘，则尝试从 C 启动。
  * 引导扇区加载程序(boot sector loader)。它从启动磁盘加载第一个 512 字节扇区到 RAM 并跳转到它。这就是本论文中描述的引导加载程序的起点。
  * BIOS 中断。这些是简单的设备驱动程序，程序可以用它们来访问屏幕、键盘和磁盘。引导加载程序依赖它们，大多数操作系统不依赖(Linux 内核一旦启动后就不使用 BIOS 中断)。MSDOS 确实使用 BIOS 中断。
  
除了主 BIOS 之外，还有扩展 ROM(extension ROM)，它们由主 BIOS 启动。每个 VGA 卡都有一个。SCSI 主机适配器和以太网卡也可以有扩展 ROM。甚至可以在以太网卡上放置一个 EPROM，以便在没有磁盘的情况下通过网络启动机器。

就启动加载设施而言，PC BIOS 与其他计算机系统相比非常原始。它关于磁盘唯一了解的就是如何加载第一个 512 字节扇区。

  软盘的第一个扇区可以加载到地址 0000:7C00。扇区的最后两个字节会被检查是否为值 0x55 和 0xAA，这作为一种粗略的校验。如果这些没问题，BIOS 就跳转到地址 0000:7C00。
  从硬盘启动与从软盘启动非常相似。硬盘的第一个扇区(通常称为主引导记录 Master Boot Record)被加载到 0000:7C00，然后 BIOS 跳转到它。MBR 程序必须将自己移动到不同于 0000:7C00 的地址，因为它应该从分区加载另一个引导扇区到地址 0000:7C00 并跳转到那里。
  现代 BIOS 版本可以把 CD-ROM 上的某个文件当作软盘镜像。它们通过加载文件的前 512 字节到 0000:7C00 并跳转到它，来假装从软盘启动。每次使用 BIOS 例程访问同一软盘的尝试，都会被重定向到 CD-ROM 上的镜像文件。也可能支持其他启动 CD-ROM 的方式(使用模拟硬盘或完全没有磁盘模拟)。
当引导扇区被加载时，CPU 处于实模式(real mode)。对于那些不熟悉 80x86 架构的人: 与 32 位保护模式(protected mode, Linux 在其中运行)相比，实模式非常受限。例如: 只有更改段寄存器才能访问 64K 段之外的数据，而地址空间前 1MB(包含 640KB 主内存)之外的数据根本无法访问。由于 gcc 不了解实模式，用其编译的程序只能在一些技巧和严重的内存大小限制下在实模式中运行。这就是为什么大多数引导加载程序(GRUB 除外)都用汇编编写。所有引导扇区程序，即使是 GRUB 的，都是用汇编编写的。

理论上引导加载程序可以直接访问裸机来完成工作，但 512 字节对于这来说是非常小的空间。引导加载程序可以访问 BIOS 中断，这些是可以通过 INT 指令(软件中断)调用的子程序。它们只在实模式下工作。大多数引导加载程序使用以下例程。

  * INT 0x10 用于屏幕输出。
  * INT 0x16 用于键盘输入。
  * INT 0x13 用于磁盘 I/O。指定磁盘上扇区的参数的范围曾经非常有限。最初只能指定硬盘上的 1024 个柱面，而硬盘可以有更多柱面。这对允许放置引导加载程序及其访问的任何文件的位置施加了限制。你被迫在硬盘起始附近创建一个小分区并将引导加载程序放在那里。BIOS 有三类:
1995 年之前的 BIOS 版本只能访问约 500MB 的 IDE 磁盘，因为 BIOS 扇区和磁头编号直接对应于 IDE 接口上的寄存器值。
1995 年至 1998 年之间的 BIOS 版本可以访问高达约 8GB 的 IDE 磁盘。它们将 INT 0x13 调用中的柱面、磁头和扇区编号转换为能更好利用 IDE 接口允许范围的不同值。
1998 年或之后的 BIOS 版本有一个使用线性块地址的新调用接口。
在这三类中任一类里，都有一些有 bug 的 BIOS 会在更低的磁盘大小限制处停止(一个应该工作到 8GB 但停在 2GB 的第二类 BIOS)。在这种情况下，升级到新的 BIOS 版本是有意义的。
  INT 0x15 是许多 BIOS 功能的全能入口，其中之一是将数据移动到扩展内存(BIOS 需要临时切换到保护模式来做这件事)。其他功能是禁用 A20 门控和确定内存大小。
### 引导加载程序的组成部分
典型的引导加载程序由三个程序组成:

  * 引导扇区程序在启动时由 BIOS 直接加载，大小只有 512 字节。
  * 第二阶段程序由引导扇区程序加载，它执行你对引导加载程序所期望的一切。
  * 引导加载程序安装程序不在系统启动时运行，而是用于将引导加载程序和第二阶段程序安装到启动磁盘上。它们必须存放在特殊位置，所以不能用 cp 复制。
#### 引导扇区程序
引导扇区程序只能有 512 字节大小，而且并非所有 512 字节在所有情况下都可用。最后两个字节必须是 0x55 和 0xAA 供 BIOS 使用。硬盘上的主引导记录包含 64 字节的分区表，所以只有前 446 字节可以使用。如果引导扇区程序必须存在于 DOS 分区或 DOS 软盘上，引导扇区开头必须有一个参数块。

由于这些大小限制，引导扇区程序几乎是 PC 平台上仅存的真正为大小而优化、并因此必须用汇编编写的程序。此外，引导扇区程序无法完成你想让引导加载程序做的一切。通常引导扇区程序做以下事情之一(而不是在同一个程序中做全部三件事):

  * 加载另一个引导扇区。这对于存在于硬盘主引导记录中的引导扇区程序很典型。它可以找到所选活动分区的第一个扇区并链式加载它。传统上随 MS-DOS 提供的 MBR 程序无法在启动时更改活动分区。还有其他引导扇区程序让你按键选择分区，例如 LILO 的 MBR 程序。
  * 加载第二阶段引导加载程序。引导扇区程序通常无法在目录中查找具有特定名称的文件并把它加载到内存中，但也存在例外，至少对于 DOS 文件系统是如此。大多数引导扇区程序按扇区编号而不是按名称找到第二阶段。扇区编号必须由引导加载程序安装程序放入引导扇区。
  * 直接加载内核。内核通常比第二阶段引导加载程序大得多。

Linux 内核中的引导扇区程序直接将内核加载到内存中，而不需要第二阶段引导加载程序。由于内核位于软盘上的连续扇区中，无需遍历文件系统数据结构。然而，对于 bzImage 内核，引导扇区程序会耍花招; 它调用内核 setup 部分中的一个子程序来加载内核其余部分到高内存中。

引导加载程序 e2boot 适合 ext2 分区的第一个 1kB 块(它是引导扇区程序的两倍大)，但通过一些技巧它能在 ext2 分区上按名称找到内核和 RAM 盘并将它们加载到内存中。

此外，DOS 磁盘上的引导扇区不使用第二阶段引导加载程序来加载 MS-DOS 内核文件 IO.SYS 和 MSDOS.SYS。MSDOS 文件系统的结构足够简单，可以在根目录中找到具有特定名称的文件并将其加载到内存中，至少加载其中一部分。

#### 第二阶段引导加载程序
这是真正的引导程序。它包含用户界面和内核加载器。它的大小可以从 6.5 千字节(LILO)到超过 100 千字节(GRUB)。它包含以下功能:

  * 用户界面。它要么是简单的命令行(LILO 的旧版本)，要么是菜单，或两者兼有。它允许你选择任意数量的操作系统并向操作系统指定额外参数。可用选项由配置文件指定。现代版本的引导加载程序可以在位图图片中显示它们的菜单。
  * 操作系统加载器。将操作系统加载到内存中并运行它。或者，我们可以加载另一个特定于另一个操作系统的引导加载程序并让它运行。这称为链式加载(chain loading)。

LOADLIN 不是完整的引导加载程序，它只有第二阶段(没有用户界面)。它从 DOS 运行，可以利用 DOS 系统调用从磁盘读取文件。使它的任务比普通引导加载程序更困难的是，它必须能够从某些类型的内存管理器中解脱出来。

#### 引导加载程序安装程序
引导加载程序的第三部分只在引导加载程序安装到磁盘上时运行。与引导扇区程序和第二阶段不同，这是一个正常的 Linux 程序。对于 LILO，每次配置更改或任何文件更新后都必须重新运行安装程序。它执行以下任务:

  * 安装引导扇区。如果引导扇区将安装在硬盘的 MBR 或 DOS 文件系统上，则可能不会覆盖所有 512 字节，但必须保留分区表或 DOS 参数块。
  * 告诉引导扇区第二阶段引导加载程序在哪里。通常它会在引导加载程序中写入一个或多个扇区地址。
  * 告诉第二阶段引导加载程序所有相关信息在哪里(配置、内核)。LILO 就是这种情况。LILO 创建一个包含所有相关扇区地址的映射文件，并将指向映射文件的指针放到引导扇区和/或第二阶段引导加载程序中。

加载操作系统
### 加载 Linux 内核
#### Linux 内核由以下部分组成:

  * 引导扇区(见 arch/i386/boot/bootsect.S)。这只在 Linux 直接从软盘启动时才运行。
  * 带有实模式初始化代码的 setup 部分(转换到保护模式)(见 arch/i386/boot/setup.S)
  * 内核其余部分，它又由以下部分组成:
    * 保护模式初始化代码
    (见 arch/i386/boot/compressed/head.S)。
    * 解压缩程序(编译的 C 代码，见
    arch/i386/boot/compressed/misc.c 和 lib/inflate.c)。

真正的内核，它是压缩的。解压后该内核由以下部分组成:
  * 保护模式初始化代码(见 arch/i386/boot/head.S)。
  * 主 C 例程(见 init/main.c)。
  * 其余所有部分。与本讨论相关的是 RAM 盘驱动程序(见 drivers/block/rd.c)。这将在第 4 节中进一步说明
  
Linux 引导加载程序应支持以下任务:

  * 将 Linux 内核加载到内存中。
    * 引导扇区(不会运行)和内核的 setup 部分被加载到低内存顶部附近(通常是地址 9000:0000)。
    * 如果不是 bzImage 类型的内核，内核其余部分将加载到低内存 0000:1000 处。
    * 如果是 bzImage 类型的内核，内核其余部分将加载到高内存，从 0x100000 开始。

引导加载程序不知道也不关心内核其余部分包含一个压缩部分。
  向内核传递命令行。这个命令行可以来自配置文件，也可以由用户交互输入。
  将初始 RAM 盘加载到内存中并将其传递给内核。初始 RAM 盘将加载到高内存顶部，位于内核之上。
  启动内核。引导加载程序必须在 setup 部分设置一些相关参数并跳转到它。从那里内核接管控制权，引导加载程序的部分就结束了。接下来内核如下启动:
    setup 代码保存相关参数和命令行以备后用。
    setup 代码检查有多少可用内存，执行一些硬件初始化并准备进入保护模式。
    在保护代码中，内核其余部分被解压。
    解压后，head.S 和主 C 例程将初始化内核的所有部分。这会显示大量消息。
    最后启动 init 进程(或首先在初始 RAM 盘上启动其 linuxrc 变体)。
#### 链式加载
大多数引导加载程序被设计为只引导一个操作系统。LILO 只知道加载 Linux 内核，而 DOS 引导扇区只能加载 DOS。如果你想在几个不同的操作系统之间选择，不太可能找到一个能加载全部的操作系统。但至少每个操作系统都应由一个可由 BIOS 加载的 512 字节引导扇区引导，关键就在于此。任何足够高级的引导加载程序都支持链式加载。

如果一个引导加载程序加载了另一个操作系统的引导扇区，这称为链式加载。这个引导扇区可以直接从磁盘或分区加载，也可以从文件加载。对于另一个操作系统来说，其引导扇区是由 BIOS 还是由另一个引导加载程序加载应该没有区别。实际上，分区的引导扇区通常由主引导记录程序加载。此外在这种情况下，由更高级的引导加载程序(如 LILO)加载也应该没有区别。

以下链式加载场景是可能的。

  Linux 引导加载程序可以链式加载几乎任何其他操作系统。
  Linux 引导加载程序可以被其他操作系统的引导管理器链式加载。可以从 Windows NT 引导管理器或 OS/2 引导管理器启动 Linux。
  Linux 引导加载程序也可以链式加载 Linux 引导加载程序。这在安装了几个独立 Linux 系统的计算机上可能是有意义的，每个 Linux 安装都有自己的本地 LILO，可以由一个中心 LILO 实例选择来链式加载它们。LILO 实例之间甚至可以交换命令行。
#### 配置引导加载程序
LILO 和 GRUB 都有一个配置文件，指定了几个菜单选项，每个代表要引导的 Linux 内核或不同的操作系统。对于每个 Linux 内核，可以指定命令行和初始 RAM 盘。除了语法细节外，这些配置文件的内容看起来非常相似。但有一个本质区别:

  LILO 在安装时读取其配置文件。每次配置文件、内核或任何初始 RAM 盘更改时，都必须重新运行 LILO 安装程序。启动时不读取配置文件。LILO 的第二阶段引导程序不知道如何在文件系统中查找文件。它依赖映射文件来查找所需文件的数据块。这个映射文件由 LILO 安装程序创建。
  GRUB 以及 SYSLINUX 在启动时读取它们的配置文件。你可以一次性安装引导加载程序，然后毫无麻烦地更改配置文件、内核和 RAM 盘镜像。第二阶段引导程序知道如何在文件系统中查找文件。
