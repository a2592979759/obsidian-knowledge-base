## MAC 地址
```链路层地址有多种叫法：局域网地址、物理地址或 MAC 地址。```

术语“地址解析”指的是在网络中查找某台计算机地址的过程。该地址是“解析”出来的，其过程是：由本地计算机上执行的客户端进程向远程计算机上执行的服务器进程发送一条信息。服务器收到的信息使服务器能够唯一识别出需要该地址的网络系统，从而提供所需的地址。当客户端收到服务器发来的、包含所需地址的响应时，地址解析过程即告完成。

因此，具有多个网络接口的主机或路由器会关联多个链路层地址，就如同它也会关联多个 IP 地址一样。但值得注意的是，链路层交换机（link-layer switch）在其连接主机与路由器的接口上并不关联链路层地址。这是因为链路层交换机的任务是在主机与路由器之间承载数据报（datagram）；交换机透明地完成这一任务，也就是说，主机或路由器无需显式地将帧寻址到中间的交换机。对于大多数局域网（包括以太网和 802.11 无线局域网）来说，MAC 地址长度为 6 字节，因此共有 2^48 种可能的 MAC 地址。

![[_assets/mac_address.png]]

尽管可以通过软件修改 MAC 地址，但在大多数情况下 MAC 地址是固定的。IEEE 负责管理 MAC 地址空间。具体来说，当一家公司想要制造适配器时，它只需支付一笔象征性的费用就能购买一块由 2^24 个地址组成的地址空间。IEEE 通过固定 MAC 地址的前 24 位的来分配这 2^24 个地址，并让公司为每个适配器自由组合后 24 位以生成唯一的地址。

适配器的 MAC 地址具有扁平结构（与层次化结构相对），无论适配器去哪里都不会改变。适配器的 MAC 地址类似于一个人的社会保障号（social security number），后者同样具有扁平寻址结构，无论这个人去哪里都不会改变。

当一个适配器想要向某个目标适配器发送帧时，发送适配器会把目标适配器的 MAC 地址插入到帧中，然后将帧发送到局域网中。

事实上，拥有链路层地址的不是主机和路由器，而是它们的**适配器（即网络接口）**。因此，具有多个网络接口的主机或路由器会关联**多个链路层地址**，就如同它也会关联**多个 IP 地址**一样。但值得注意的是，链路层交换机**不**在其连接主机与路由器的接口上关联链路层地址。

## 地址解析协议 (Address Resolution Protocol, ARP)
```其功能是将 IP 地址转换为物理地址。```

![[_assets/mac_network.png]]

假设 IP 地址为 222.222.222.220 的主机想要向主机 222.222.222.222 发送一个 IP 数据报。在本例中，源和目的地址位于同一子网（就第 4.4.2 节的寻址意义而言）。为了发送数据报，源主机必须不仅把 IP 数据报交给适配器，还要给出目标 222.222.222.222 的 MAC 地址。然后发送适配器会构建一个包含目标 MAC 地址的链路层帧，并将该帧发送到局域网中。

ARP 将 IP 地址解析为 MAC 地址。它在很多方面类似于 DNS（在第 2.5 节中研究），后者将主机名解析为 IP 地址。然而，这两种解析器的一个重要区别在于：DNS 解析的是互联网上任意位置的主机名，而 ARP 只为**同一子网内**的主机和路由器接口解析 IP 地址。

![ARP 功能](https://media.geeksforgeeks.org/wp-content/uploads/20190423135210/arpp.png)

### ARP 缓存表
每台主机和路由器的内存中都有一张 ARP 表（ARP table），其中包含 IP 地址到 MAC 地址的映射。

![[_assets/arp_table.png]]

ARP 表还包含一个生存时间（time-to-live, TTL）值，指示每条映射何时会被从表中删除。请注意，表**并不一定**包含子网上每台主机和路由器的条目；有些可能从未被录入表中，另一些则可能已经过期。一个条目典型的过期时间是从它被放入 ARP 表起 20 分钟。

### ARP 报文及其格式
ARP 协议可能发送四种类型的 ARP 报文。它们由 ARP 报文“操作（operation）”字段中的四个值标识。报文类型为：

1. **ARP-Request**（广播，请求者的源 IP 地址）
2. **ARP-Reply**（单播给请求者，即目标）

### 地址解析过程
```ARP 请求是广播，ARP 响应是单播。```

如果发送者的 ARP 表中已有目标节点的条目，那么这项任务就很简单。如果没有，首先发送者会构造一个称为 ARP 报文（ARP packet）的特殊数据包。ARP 报文包含多个字段，包括发送和接收的 IP 与 MAC 地址。ARP 查询报文和响应报文格式相同。ARP 查询报文的目的是查询子网上所有其他主机和路由器，以确定与正在解析的 IP 地址相对应的 MAC 地址。

例如，222.222.222.220 将 ARP 查询报文交给适配器，并告知适配器应将报文发送到 MAC 广播地址，即 FF-FF-FF-FF-FF-FF。适配器把 ARP 报文封装在链路层帧中，使用广播地址作为帧的目标地址，并将帧发送到子网中。

包含 ARP 查询的帧会被子网上所有其他适配器接收，并且（由于广播地址）每个适配器都会把帧中的 ARP 报文向上传递给各自的 ARP 模块。每个 ARP 模块检查自己的 IP 地址是否与 ARP 报文中的目标 IP 地址匹配。匹配的那个会向查询主机发回带有所需映射的 ARP 响应报文。然后查询主机 222.222.222.220 就可以更新它的 ARP 表并发送其 IP 数据报，该数据报被封装在目标 MAC 为先前响应 ARP 查询的主机或路由器的链路层帧中。

![ARP 过程](https://media.geeksforgeeks.org/wp-content/uploads/arp-2.jpg)

### 场景

1. **情形1：发送者是主机，想要向同一网络中的另一台主机发送数据包**。
    - 使用 ARP 查找另一台主机的物理地址
2. **情形2：发送者是主机，想要向另一个网络中的另一台主机发送数据包**。
    - 发送者查看其路由表。
    - 找到该目的地址的下一跳（路由器）的 IP 地址。
    - 使用 ARP 查找路由器的物理地址
3. **情形3：发送者是路由器，接收到一个发往另一个网络上主机的数据报**。
    - 路由器检查其路由表。
    - 找到下一个路由器的 IP 地址。
    - 使用 ARP 查找下一个路由器的物理地址。
4. **情形4：发送者是路由器，接收到一个发往同一网络内主机的数据报**。
    - 使用 ARP 查找该主机的物理地址。

### 与 ARP 相关的术语

1. ARP 缓存：解析出 MAC 地址后，ARP 将其发送给源端，源端将其存储在一张表中以备将来参考。后续通信可以使用表中的 MAC 地址
2. ARP 缓存超时（TTL）：它指示 ARP 缓存中的 MAC 地址可以驻留的时间
3. ARP 请求：这本质上是在网络上广播一个数据包，以验证是否遇到了目标 MAC 地址。
发送者的物理地址。
发送者的 IP 地址。
接收者的物理地址为 FF:FF:FF:FF:FF:FF 或全 1。
接收者的 IP 地址
4. ARP 响应/回复：这是源端从目标端收到的 MAC 地址响应，有助于后续数据的进一步通信。

### ARP 的层次

正如我们所看到的，ARP 报文被封装在链路层帧中，因此在架构上位于链路层之上。然而，ARP 报文含有链路层地址字段，因此可以说它是一个链路层协议；但它也包含网络层地址，因此也可以说它是一个网络层协议。归根结底，ARP 很可能最好被视为一个跨越链路层与网络层边界之间的协议。
