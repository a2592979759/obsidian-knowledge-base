### IPv4
IPv4 是一种用于分组交换网络的无连接协议。它采用***尽力而为 (best effort)*** 的交付模型，既不保证交付，也不确保正确的排序或避免重复交付。

IPv4 使用 32 位（4 字节）寻址，提供 2^32 个地址。IPv4 地址采用点分十进制记法书写，由地址的四个八位组分别以十进制表示并用句点分隔，例如 192.168.1.5。

### IPv4 数据报头部
![[_assets/ip_packet.png]]

- 版本号 (Version number)。这 4 位指定数据报的 IP 协议版本。
- 头部长度 (Header length)。由于一个 IPv4 数据报可以包含可变数量的选项（这些选项包含在 IPv4 数据报头部中），因此需要这 4 位来确定数据在 IP 数据报中实际上从哪里开始。
- 服务类型 (Type of service)。服务类型 (TOS) 位被包含在 IPv4 头部中，以便允许不同类型的 IP 数据报（例如，特别需要低延迟、高吞吐量或可靠性的数据报）相互区分。
- 数据报长度 (Datagram length)。这是 IP 数据报（头部加数据）的总长度，以字节为单位。
- 标识符、标志、分片偏移 (Identifier, flags, fragmentation offset)。这三个字段与所谓的 IP 分片有关。
- 生存时间 (Time-to-live)。生存时间 (TTL) 字段被包含进来以确保数据报不会在网络中无限循环（例如，由于长期存在的路由环路）。每当地址报被路由器处理一次，该字段就减一。如果 TTL 字段达到 0，则必须丢弃该数据报。
- 协议 (Protocol)。该字段仅在 IP 数据报到达其最终目的地时使用。该字段的值指示此 IP 数据报的数据部分应当传递给哪个特定的传输层协议。
- 头部校验和 (Header checksum)。头部校验和帮助路由器检测接收到的 IP 数据报中的位错误。
- 源和目的 IP 地址 (Source and destination IP addresses)。
- 选项 (Options)。选项字段允许扩展 IP 头部。
- 数据（载荷）(Data payload)。在大多数情况下，IP 数据报的数据字段包含要交付到目的地的传输层报文段（TCP 或 UDP）。

注意，一个 IP 数据报总共有 20 字节的头部（假设没有选项）。如果数据报携带一个 TCP 报文段，那么每个（未分片）数据报总共携带 40 字节的头部（20 字节 IP 头部加 20 字节 TCP 头部）以及应用层消息。

### IP 数据报分片
```并非所有链路层协议都能承载相同大小的网络层数据包。```

例如，以太网帧最多可承载 1,500 字节的数据，而某些广域网链路的帧最多只能承载 576 字节。链路层帧能承载的最大数据量称为***最大传输单元 (maximum transmission unit, MTU)***。由于每个 IP 数据报被封装在链路层帧中以从一个路由器传输到下一个路由器，链路层协议的 MTU 对 IP 数据报的长度施加了硬性限制。

解决办法是将 IP 数据报中的数据分片成两个或更多更小的 IP 数据报，将每个更小的 IP 数据报分别封装在单独的链路层帧中，并在输出链路上发送这些帧。每个更小的数据报被称为一个***分片 (fragment)***。

分片需要在到达目的地的传输层之前重组。实际上，TCP 和 UDP 都期望从网络层接收到完整的、未分片的报文段。IPv4 的设计者决定将数据报重组的工作放在终端系统而不是网络路由器中。

为了让目的主机能够执行这些重组任务，IP（版本 4）的设计者在 IP 数据报头部中加入了标识符、标志和分片偏移字段。
