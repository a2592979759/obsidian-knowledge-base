## 路由器 (Router)

```路由器是网络层设备，而交换机是链路层设备```

一些分组交换机（称为链路层交换机，在第 5 章研究）根据链路层帧字段中的值来做转发决定；因此交换机被称为链路层（第二层）设备。另一些分组交换机（称为路由器）根据网络层字段的值来做转发决定。因此路由器是网络层（第三层）设备。但它们也必须实现第二层协议，因为第三层设备需要第二层的服务来实现它们的（第三层）功能。

## 路由器内部
```路由器的主要职责 - 转发功能：数据包从路由器的输入链路实际传输到该路由器的适当输出链路。```

### 路由器架构：
- **输入端口 (Input ports)**
    - 它执行***物理层功能***，在路由器处终止一条输入物理链路。
    - 输入端口还执行与输入链路另一侧的链路层互操作所需的***链路层功能***。
    - 也许最关键的是，***查找功能***也是在输入端口执行的；正是在这里查阅转发表，以确定到达的数据包将通过交换结构 (switching fabric) 被转发到哪个路由器输出端口。***控制数据包***（例如，携带路由协议信息的数据包）从输入端口被转发到路由处理器。
- **交换结构 (Switching fabric)**
    - 交换结构将路由器的输入端口连接到它的输出端口。
- **输出端口 (Output ports)**
    - 输出端口存储从交换结构接收到的数据包，并通过执行必要的***链路层和物理层功能***在输出链路上传输这些数据包。
- **路由处理器 (Routing processor)**
    - 路由处理器执行路由协议。
    - 维护路由表。
    - 连接链路的状态信息。
    - 为路由器计算转发表。
    - 它还执行网络管理功能。

![[_assets/router_arch.png]]

路由器的输入端口、输出端口和交换结构共同实现转发功能，并且几乎总是以***硬件***实现。这些转发功能有时被统称为路由器***转发数据面 (forwarding data plane)***。

这些路由器控制面功能通常以***软件***实现，并在路由处理器（通常是一个传统的 CPU）上执行。

### 输入处理
输入端口的线路终端功能和链路层处理为那条单独输入链路实现物理层和链路层。输入端口执行的查找是路由器操作的核心——正是在这里路由器使用转发表来查找到达的数据包将通过交换结构被转发到的输出端口。转发表由路由处理器计算和更新，***通常在每个输入端口存储一份影子副本***。转发表通过一条独立的总线（例如 PCI 总线，由从路由处理器到输入线路卡之间的虚线表示）从路由处理器复制到线路卡。因此，转发决定可以在***本地***、在每个输入端口做出，而无需为每个数据包调用集中的路由处理器，从而避免了集中式处理的瓶颈。

![[_assets/input_processing.png]]

这里有四个主要事件发生：

- 路由表查找。
- 必须执行物理层和链路层处理，如上所述；
- 数据包的版本号、校验和和生存时间字段——都必须检查，后两个字段必须被重写。
- 用于网络管理的计数器（例如，接收到的 IP 数据报数量）必须被更新。

### 交换
```确保数据包从输入端口被交换（即转发）到输出端口。```

有三种交换方法：

- **通过内存交换 (Switching via memory)**。带有到达数据包的输入端口首先通过中断通知路由处理器。然后数据包从输入端口被复制到处理器内存。路由处理器随后从头部提取目的地址，在转发表中查找适当的输出端口，并将数据包复制到输出端口的缓冲区。（内存映射端口）
- **通过总线交换 (Switching via a bus)**。在这种方法中，输入端口通过共享总线将数据包直接传输到输出端口，无需路由处理器的介入。
- **通过互连网络交换 (Switching via an interconnection network)**。克服单个共享总线带宽限制的一种方法是使用更复杂的互连网络，例如过去在多处理器计算机架构中用来互连处理器的那些网络。

![[_assets/switching_method.png]]

### 输出处理

输出端口处理，接收已存储在输出端口内存中的数据包并通过输出链路传输它们。这包括：

- 选择并出队等待传输的数据包。
- 执行所需的链路层和物理层传输功能。

![[_assets/output_process.png]]

### 转发表
```每个路由器都有一个转发表。它规定数据包应被转发到哪个端口。```

路由器通过检查到达数据包头部中某个字段的值来转发数据包，然后使用此头部值在路由器的转发表中索引。转发表条目中为该头部存储的值指示该数据包应当被转发到的路由器输出链路接口。根据网络层协议，头部值可以是数据包的目的地址，或者是该数据包所属连接的指示。

![[_assets/routing.png]]

采用这种样式的转发表，路由器将数据包目的地址的前缀与表中的条目进行匹配；如果匹配，路由器将数据包转发到与该匹配关联的链路。路由器使用**最长前缀匹配规则 (longest prefix matching rule)**；也就是说，它找到表中匹配最长的条目，并将数据包转发到与最长前缀匹配相关联的链路接口。

虽然数据报网络中的路由器不维护连接状态信息，但它们确实在转发表中维护转发状态信息。然而，这些转发状态信息变化的时间尺度相对较慢。实际上，在数据报网络中，转发表由路由算法修改，这些算法通常大约每一到五分钟更新一次转发表。

### 路由表
```每个路由器维护一张路由表。路由器的路由表既包括路由器的距离向量，也包括路由器的转发表。```

回想一下，RIP 路由器大约每 30 秒交换一次通告。如果路由器至少每 180 秒没有听到邻居的消息，该邻居就被认为不再可达。当这种情况发生时，RIP 修改本地路由表，然后通过向其邻居路由器（那些仍然可达的）发送通告来传播此信息。路由器也可以使用 RIP 的请求报文请求有关其邻居到给定目的的代价的信息。路由器之间通过 UDP 使用**端口号 520** 相互发送 RIP 请求和响应报文。**UDP 报文段**在标准 IP 数据报中在路由器之间承载。

![[_assets/Routing_table.png]]

下图勾勒出 RIP 在 UNIX 系统中通常是如何实现的，例如，一个充当路由器的 UNIX 工作站。一个名为 routed（发音为“route dee”）的进程执行 RIP，即维护路由信息并与运行在相邻路由器中的 routed 进程交换消息：

![[_assets/RIP_implement.png]]

因为 RIP 被实现为应用层进程（尽管是一个能够操纵 UNIX 内核内路由表的非常特殊的进程），它可以通过标准套接字发送和接收消息，并使用标准传输协议。

尽管这里讨论的是 RIP，但**OSPF** 才是常用来更新路由器路由表的自治系统内部路由协议。

### 条目如何进入路由器的转发表？

当数据包到达路由器时，数据包的目的 IP 地址与转发表中的前缀进行比较，以找到最长前缀匹配的那个。然后数据包在路由器内部被转发到与该前缀关联的路由器端口。为了让事情变得有趣，假设该前缀是一个“外部前缀”，即它不属于路由器的 AS，而属于某个其他 AS。

1. 通过**BGP 路由通告**了解该前缀（对应于一个子网或若干子网的聚合）。这样的通告可以通过 eBGP 会话（来自另一个 AS 中的路由器）或通过 iBGP 会话（来自同一 AS 中的路由器）发送给它。
2. 如果路由器收到针对此前缀的多条路由通告，路由器使用 BGP 路由选择过程来找到该前缀的最佳路由。
3. 假设已选中这样一条最佳路由。如前所述，选中的路由包含一个 NEXT-HOP 属性，它是沿此最佳路由上路由器 AS 之外第一个路由器的**IP 地址**。
4. 然后路由器使用其**AS 内部路由协议（通常是 OSPF）**来确定到 NEXT-HOP 路由器的最短路径。
5. 路由器最终通过识别该最短路径上的第一条链路来确定与该前缀关联的**端口号**。
6. 然后路由器就能把前缀-端口对录入它的转发表！由路由处理器计算出的转发表随后被推送到路由器的输入**端口线路卡**。

### 路由信息库 (RIB) 与转发信息库 (FIB)

![[_assets/RIB_FIB.png]]

**路由信息库 (Routing Information Base, RIB)** 是存储在路由器或联网计算机中的数据表，列出了到特定网络目的地的路由，并在某些情况下列出与这些路由关联的度量（距离）。路由表包含紧邻它周围的网络拓扑信息。路由表的构建是路由协议的主要目标。静态路由是以非自动方式作为路由表条目输入的，是固定的，而非某种网络拓扑“发现”过程的结果。

基本上，show ip route 显示的是 FIB，它是来自每个 RIB 的最佳路由的集合。每个路由协议都会有一个关联的 RIB。BGP 的所有路由会有一个路由数据库，而 OSPF 的所有路由也会有单独的路由数据库 (RIB)。例如，OSPF/IS-IS 数据库、EIGRP 拓扑表或 BGP 表。从其中每一个优选出的路由会被加载到快速查找 ASIC 中，以便在快速路径内存中实现线速转发。

**转发信息库 (Forwarding information base, FIB)**，也称为转发表，最常用于网络桥接、路由和类似功能中，以找到输入接口应将数据包发送到哪个适当的接口，从而由路由器传输。与路由信息库 (RIB)（也称为路由表）相反，FIB 针对目的地址的快速查找进行了优化。

转发信息库 (FIB) 和 Cisco 快速转发 (Cisco Express Forwarding, CEF) 被引入以使**第三层交换性能保持一致**。当 IP 路由从 RIB 复制到 FIB 时，它们的下一跳会被解析，输出接口会被计算，并且当下一跳解析导致到同一目的地的多条路径时会创建多个条目。

展示 CEF (RIB) 的示例：

    RR#show ip cef 10.0.11.11 detail
    10.0.11.11/32, epoch 0, flags rib only nolabel, rib defined all labels
    recursive via 10.0.1.1
        nexthop 10.0.2.1 FastEthernet0/0 label 19
