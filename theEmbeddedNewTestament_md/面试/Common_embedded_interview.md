## ***预处理器（Preprocessor）***
**问题：如何使用 #define 语句声明一个返回一年内秒数的清单常量（manifest constant）？在回答中忽略闰年。**

    #define SECONDS_PER_YEAR (60UL * 60UL * 24UL * 365UL)

**要点**：

* 对 #define 语法的基础了解（即结尾不能有分号、需要加上括号等）。

* 选择好的名称，使用大写字母和下划线。

* 理解预处理器会为你计算常量表达式。因此，把你在计算一年秒数的过程明确写出来，比自己实际算出来更清晰，而且没有性能损失。

* 认识到该表达式在 16 位机器上会溢出整型参数——因此需要 L，告诉编译器将该表达式当作长整型（Long）处理。

* 作为加分项，如果你在表达式中加上 UL（表示无符号长整型, unsigned long），那么你已经开了个好头，因为你表明自己注意到了有符号类型和无符号类型（signed/unsigned）的隐患——记住，第一印象很重要！

**问题：编写"标准"的 MIN 宏。也就是说，一个接受两个参数并返回其中较小者的宏。**

    #define MIN(A,B) ((A) <= (B) ? (A) : (B))
    
**要点**：

* 对在宏（macro）中使用的 #define 指令的基础了解。这很重要，因为在内联运算符（inline operator）成为标准 C 的一部分之前，宏是生成内联代码（inline code）的唯一可移植方式。在嵌入式系统中，为了达到所需的性能水平，内联代码往往是必需的。

* 对三元条件运算符（ternary conditional operator）的了解。它在 C 中存在，是因为它能让编译器相比 if-then-else 序列生成更优的代码。鉴于性能在嵌入式系统里通常是个问题，理解并使用这种结构很重要。

* 理解需要非常仔细地给宏的参数加括号。

* 我还会用这道题来引出关于宏的副作用（side effects）的讨论，例如当你编写如下代码时会发生什么：

    least = MIN(*p++, b);

**问题：预处理器指令 #error 的用途是什么？**

**要点**：

* 你要么知道答案，要么不知道。如果不知道，请参阅参考资料 1。这道题非常有用，可以用来区分普通人（normal folks）和极客（nerds）。只有真正读过 C 教材附录的极客才会发现这类东西。当然，如果你不是要找极客，那么候选人最好祈祷自己不知道答案。

## ***死循环（Infinite Loops）***
**问题：死循环在嵌入式系统中经常出现。在 C 中如何编写一个死循环？**

对于这个问题有几种解法。我偏好的解法是：

    while(1)

    {

    …

    }

    另一种常见的结构是：

    for(;;)

    {

    …

    }

就我个人而言，我不喜欢这种结构，因为其语法并不能准确地说明具体发生了什么。因此，如果候选人给出这个作为答案，我会借此机会探究他们这样做的理由。如果他们的回答基本就是——"我就是被教这样写，之后再没想过"——那这向我透露了一些关于他们（不好的）信息。反之，如果他们说明这是 K&R 偏好的方法，并且是唯一能让死循环通过 Lint 检查的写法，那他们会获得加分。

第三种解法是使用 goto：

    Loop:

    …

    goto Loop;

提出这种解法的候选人要么是汇编语言程序员（这可能是好事），要么是准备进入新领域、深藏不露的 BASIC/FORTRAN 程序员。

## ***数据声明（Data declarations）***
**问题：使用变量 a，写出以下各项的定义：**

    (a) 一个整数（integer）
    (b) 一个指向整数的指针
    (c) 一个指向整数指针的指针
    (d) 一个包含十个整数的数组
    (e) 一个包含十个整数指针的数组
    (f) 一个指向包含十个整数数组的指针
    (g) 一个指向函数的指针，该函数接受一个整数参数并返回一个整数
    (h) 一个包含十个函数指针的数组，这些函数接受一个整数参数并返回一个整数。

**答案：**

    (a) int a; // 一个整数
    (b) int *a; // 一个指向整数的指针
    (c) int **a; // 一个指向整数指针的指针
    (d) int a[10]; // 一个包含 10 个整数的数组
    (e) int *a[10]; // 一个包含 10 个整数指针的数组
    (f) int (*a)[10]; // 一个指向包含 10 个整数的数组的指针
    (g) int (*a)(int); // 一个指向函数 a 的指针，该函数接受一个整数参数并返回一个整数
    (h) int (*a[10])(int); // 一个包含 10 个函数指针的数组，这些函数接受一个整数参数并返回一个整数

人们常说其中几个是需要在教材中查的内容——我同意。在写这篇文章时，我也参考了教材来确保语法正确。然而，我预期自己在面试时会被问到这道题（或与之相近的题）。因此，我确保自己知道答案——至少在这几个小时的面试里。不知道答案（或至少其中大部分）的候选人，只是单纯地没有为面试做好准备。如果他们连面试都无法准备，那他们还能准备什么？

## ***静态（Static）***
**问题：关键字 static 有哪些用途？**

**答案：**

这个简单的问题很少能被完整地回答。static 在 C 中有三种不同的用途：

    (a) 在函数体内声明为 static 的变量，会在函数调用之间保持其值。

    (b) 在模块 [1] 内（但在函数体外）声明为 static 的变量，可以被该模块内的所有函数访问。它不能被任何其他模块内的函数访问。也就是说，它是一个局部化的全局变量（localized global）。

    (c) 在模块内声明为 static 的函数，只能被该模块内其他的函数调用。也就是说，该函数的作用域被局部化到声明它的模块内。

大多数候选人能答对第一部分。有相当一部分人能答对第二部分，而能理解答案 (c) 的人则少得可怜。这对候选人来说是一个严重的弱点，因为他们显然不理解将数据和代码的作用域局部化的重要性和好处。

## ***常量（Const）***
**问题：关键字 const 是什么意思？**

**答案：**

一旦面试者说出"const 的意思是常量（constant）"，我就知道我面对的是一位业余人士。Dan Saks 在过去一年里已经详尽地论述过 const，以至于每位 ESP 的读者都应该非常清楚 const 能做什么、不能做什么。如果你没读过那个专栏，那么只需要说 const 表示"只读（read-only）"就够了。虽然这个答案并没有真正地讲透这个主题，但我会接受它作为一个正确答案。（如果你想要详细的答案，那就仔细去读 Saks 的专栏！）

如果候选人对答正确，那么我会接着问他这些补充问题：

**问题：以下这些不完整的 [2] 声明各是什么意思？**

    const int a;
    int const a;
    const int *a;
    int * const a;
    int const * a const;

前两个意思相同，即 a 是一个 const（只读）整数。第三个意思是 a 是一个指向 const 整数的指针（也就是说，这个整数不能被修改，但指针可以修改）。第四个声明 a 是一个指向整数的 const 指针（也就是说，a 所指向的整数可以被修改，但指针本身不能）。最后一个声明 a 是一个指向 const 整数的 const 指针（也就是说，a 所指向的整数和指针本身都不能被修改）。

如果候选人能正确回答这些题，我会印象深刻。

顺便说一下，有人可能会疑惑，既然不用 const 也很容易写出一个功能正确的程序，那为什么我如此强调 const。原因有几个：

* 使用 const 能向阅读你代码的人传达一些非常有用的信息。实际上，把参数声明为 const 就告诉用户它的预期用途。如果你花大量时间清理别人留下的烂摊子，那你会很快学会欣赏这一点额外信息。（当然，使用 const 的程序员很少会给别人留下需要清理的烂摊子……）

* const 有可能通过给优化器提供一些额外信息来生成更紧凑的代码。

* 大量使用 const 的代码天然地被编译器保护，避免因粗心编码导致那些本不该被修改的参数被修改。简而言之，这样的代码往往缺陷更少。

## ***易变（Volatile）***
**问题：关键字 volatile 是什么意思？给出三个不同的使用例子。**

易变变量（volatile variable）是指可能意外改变的变量。因此，编译器无法对该变量的值做任何假设。特别地，优化器必须小心地在每次使用时重新加载该变量，而不是在寄存器中保存一份副本。易变变量的例子有：

* 外设中的硬件寄存器（例如状态寄存器）
* 在中断服务例程（ISR）中引用的非栈变量。
* 在多线程应用中由多个任务共享的变量。

如果候选人不知道这道题的答案，那他们不会被录用。我认为这是区分"C 程序员"和"嵌入式系统程序员"的最基本的问题。嵌入式开发者要与硬件、中断、RTOS 等打交道。所有这些都需要易变变量。不理解 volatile 的概念会导致灾难。

在面试者（或许）答对这题的（可疑的）假设下，我喜欢再深入挖掘一下，看看他们是否真正理解 volatile 的全部意义。特别地，我会问他们以下问题：

**问题：**
* 一个参数能否同时既是 const 又是 volatile？解释你的答案。
* 一个指针能否是 volatile？解释你的答案。
* 以下函数有什么问题？

        int square(volatile int *ptr) {
            return *ptr * *ptr;
        }

**答案：**

* 可以。一个例子是只读状态寄存器。它是 volatile 的，因为它可能意外改变。它是 const 的，因为程序不应尝试修改它。

* 可以。虽然这不太常见。一个例子是中断服务例程修改一个指向缓冲区的指针。

* 这个很刁钻。这段代码的意图是返回 *ptr 所指值的平方。然而，由于 *ptr 指向一个 volatile 参数，编译器会生成类似这样的代码：

        int square(volatile int *ptr) {
            int a,b;
            a = *ptr;
            b = *ptr;
            return a * b;
        }

由于 *ptr 的值可能意外改变，所以 a 和 b 可能不同。因此，这段代码可能返回一个不是平方的数字！正确的写法是：

    long square(volatile int *ptr) {
        int a;
        a = *ptr;
        return a * a;
    }

## ***位操作（Bit Manipulation）***
**问题：嵌入式系统总是要求用户操作寄存器或变量中的位。给定一个整型变量 a，编写两段代码片段。第一段设置 a 的第 3 位。第二段清除 a 的第 3 位。两种情况都要求其余位保持不变。**

**答案：**

对于这道题有三种基本回答：

* 不知道。面试者不可能做过任何嵌入式系统工作。

* 使用位域（bit fields）。位域和三元组（trigraphs）一样，都是 C 中最脑残的部分。位域在不同编译器之间天生不可移植，因此能保证你的代码不可复用。我最近不幸看过 Infineon 为它们某个更复杂的通信芯片编写的驱动。它使用了位域，结果完全没用，因为我的编译器以相反的方式实现了位域。教训——永远不要让非嵌入式的人靠近真正的硬件！[3]

* 使用 #define 和位掩码（bit masks）。这是一种高度可移植的方法，也是应该使用的方法。我对这个问题的最优解是：

        #define BIT3 (0x1 << 3)
        static int a;

        void set_bit3(void) {
            a |= BIT3;
        }

        void clear_bit3(void) {
            a &= ~BIT3;
        }

有些人喜欢定义一个掩码，连同用于置位和清零值的清单常量一起。这也是可以接受的。我寻找的关键要素是使用清单常量，以及 |= 和 &= ~ 结构。

## ***访问固定内存位置（Accessing fixed memory locations）***
**问题：嵌入式系统的特点往往是要求程序员访问特定的内存位置。在某个项目中，需要将位于绝对地址 0x67a9 的整型变量设置为值 0xaa55。编译器是纯 ANSI 编译器。编写代码来完成这个任务。**

这个问题测试你是否知道：为了访问一个绝对位置，把一个整数强制转换（typecast）成指针是合法的。确切的语法因个人风格而异。不过，我通常会寻找类似这样的写法：

    int *ptr;
    ptr = (int *)0x67a9;
    *ptr = 0xaa55;

一种更迷惑人的写法是：

    *(int * const)(0x67a9) = 0xaa55;

即便你更喜欢第二种解法，我建议在面试场合使用第一种解法。

## ***中断（Interrupts）***
**问题：中断是嵌入式系统的重要组成部分。因此，许多编译器厂商为标准 C 提供一个扩展来支持中断。通常，这个新关键字是 __interrupt。以下代码使用 __interrupt 定义一个中断服务例程。请评价这段代码。**

    __interrupt double compute_area(double radius) {

        double area = PI * radius * radius;
        printf(“nArea = %f”, area);

        return area;
    }

**答案：**

这个函数错得太多，几乎不知道该从哪说起。

* 中断服务例程不能返回值。如果你不理解这点，那你就不会被录用。

* ISR 不能传递参数。如果你漏掉了这一点，请参见 (a) 中关于你的就业前景的内容。

* 在许多处理器/编译器上，浮点运算不一定是可重入（re-entrant）的。在某些情况下需要压入额外的寄存器，在其他情况下，你根本不能在 ISR 中做浮点运算。此外，鉴于通用经验法则是 ISR 应该短小精悍，人们会质疑在这里做浮点数学运算是否明智。

* 与 (c) 类似，printf() 在可重入性（reentrancy）和性能方面常常有问题。如果你漏掉了 (c) 和 (d) 这两点，我不会太苛责你。不用说，如果你答对了这两点，那你的就业前景会越来越好。

## ***代码示例（Code Examples）***
**问题：以下代码输出什么，为什么？**

    void foo(void) {
        unsigned int a = 6;
        int b = -20;

        (a+b > 6) ? puts(“> 6”) : puts(“<= 6”);
    }

**答案：**

这道题测试你是否理解 C 中的整型提升（integer promotion）规则——我发现很多开发者对这块理解非常差。不管怎样，答案是输出"> 6"。原因在于，涉及有符号类型和无符号类型的表达式，所有操作数都会被提升（promote）为无符号类型。因此 -20 变成一个非常大的正整数，表达式的结果大于 6。这在嵌入式系统中非常重要，因为无符号数据类型应该被频繁使用（参见参考资料 2）。如果你这道题答错了，那你就离不被录用近在咫尺了。

**问题：评价以下代码片段？**

    unsigned int zero = 0;

    unsigned int compzero = 0xFFFF; /*0 的 1 的补码 */

**答案：**

在 int 不是 16 位的机器上，这是不正确的。应该写成：

unsigned int compzero = ~0;
这道题真正检验候选人是否理解字长（word length）在计算机上的重要性。以我的经验，优秀的嵌入式程序员对底层硬件及其局限性极其敏感，而计算机程序员则倾向于把硬件当作一个必要的麻烦而不屑一顾。

到这一阶段，候选人要么已经完全灰心——要么正顺风顺水、乐在其中。如果很明显候选人水平不行，那测试就在此终止。然而，如果候选人表现良好，那我就会抛出这些补充问题。这些问题很难，我预期只有最顶尖的候选人才答得好。在提出这些问题时，我更关注候选人解决问题的思路，而不是答案本身。无论如何，玩得开心……

## ***动态内存分配（Dynamic Memory Allocation）***
**问题：虽然在非嵌入式计算机中没那么常见，但嵌入式系统仍然会从堆（heap）中动态地分配内存。在嵌入式系统里，动态内存分配有哪些问题？**

**答案：**

这里，我预期提到内存碎片（memory fragmentation）、垃圾回收（garbage collection）的问题、可变的执行时间等。这个主题在 ESP 中已被广泛论述，主要是由 Plauger 撰写的。他的解释比我能在这里提供的任何内容都更深刻，所以去读那些往期杂志吧！在让候选人陷入虚假的安全感之后，我抛出这样一个宝贝：

**问题：以下代码片段输出什么，为什么？**

    char *ptr;

    if ((ptr = (char *)malloc(0)) == NULL) {
        puts(“Got a null pointer”);
    }
    else {
        puts(“Got a valid pointer”);
    }

这是一道有趣的题。我最近才偶然发现它，当时我的一位同事无意中给 malloc 传了 0，却返回了一个合法的指针！在深入挖掘之后，我发现 malloc(0) 的结果是实现定义的，所以正确答案是"视情况而定"。我用它来开启一场讨论，探讨面试者认为 malloc 应该做什么。在这里，得到正确答案远没有你解决问题的思路和决策理由重要。

## ***类型定义（Typedef）***
***问题：Typedef 在 C 中经常用来为已有的数据类型声明同义词（synonyms）。也可以使用预处理器来做类似的事。例如，考虑以下代码片段：***

    #define dPS struct s *

    typedef struct s * tPS;

**答案：**

两种情况的意图都是把 dPS 和 tPS 定义为指向结构体 s 的指针。哪种方法（如果有的话）更可取，为什么？

这是一个非常微妙的问题，任何（以正确理由）答对的人都值得被祝贺或被谴责（不禁让人想到"找点正事做吧"）。答案是 typedef 更可取。考虑这些声明：

    dPS p1,p2;

    tPS p3,p4;

第一个展开为

    struct s * p1, p2;

它把 p1 定义为指向该结构体的指针，而 p2 定义为实际的结构体，这可能不是你想要的。第二个例子正确地定义了 p3 和 p4 为指针。

## ***晦涩的语法（Obfuscated syntax）***
***问题：C 允许一些令人震惊的结构。这个结构合法吗？如果合法，这段代码做什么？***

    int a = 5, b = 7, c;

    c = a+++b;

**答案：**

这道题意在为这个测验画上轻松的一笔，因为信不信由你，这是完全合法的语法。问题是编译器如何处理它？那些可怜的编译器作者真的为这个问题争论过，最终提出了"最大吞噬（maximum munch）"规则，它规定编译器应尽可能吞下最大的（合法）块。因此，这段代码被处理为：

    c = a++ + b;

因此，这段代码执行后，a = 6，b = 7，c = 12。

如果你知道答案，或者猜对了——那很好。如果你不知道答案，我也不认为这是问题。我发现这道题最大的好处是，它非常适合引发关于编码风格、代码评审（code review）的价值以及使用 lint 的好处的讨论。
